## Priority B: ambient lighting and G20 coding

### Dauxdu/bmw-coding  `ebb3b532dd01abe8d4a25d1bb79595a166cb376b` (2026-10-24, MIT)

`e-sys/02-Codings/Lighting/Ambient-Lighting.md`: G-series colours are coded in **BDC_BODY → 360A →
`LIC_LCI_COLOR_LIBRARY_DATA`** as RGB; the library values White `90 E0 90`, Bronze `D7 6E 14`, Orange
`93 1A 01`, Blue `00 20 FE`, Green `10 FE 32`, Violet `78 3C FE` (used as the app's "BDC library" chips);
a note that it needs a compatible BDC_BODY firmware. F-series brightness lives in FEM_BODY 3070
(`Ambiente_Helligkeit`, `Ambiente_Nachfuehrung`). `ENET-Connection.md`: ≥ 12.5 V, wait 30 s after the
OBD plug. **Medium** (community coding guide).

### aremmell/g8x-colors  `4b0ea4a511937552e00c44f8726d0013edbe4fee` (2026-01-01, MIT)

`deploy/index.php`: the BimmerCode path **`BDC_BODY3 → 360A/LIC_LCI_COLOR_LIBRARY_DATA →
360D/LIC_LCI_COLOR_PROFILES_DATA → G20G21G26G28G80_Lichpaket_code1`**; bytes **18-20** (doors and dash),
**23-25** (footwells), **28-30** (map light) hold one RGB triplet each; `onColorChange()` folds `ff` to
`fe`. The BimmerCode entry name says the layout is shared by G20/G21/G26/G28/G80, which is why the G8X
tool applies to a G20. The site's own disclaimer: written early 2024, may not match newer software.
**Medium** for the G20 layout; the FE rule is kept in `colour.codingByte()` for the coding path only (the
diagnostic actuator is documented 0..255).

### siegester03/bmw-g-series-coding  `b40f1baf7f27d2d5e9267e6f87cd4f1556ed8b9f` (2020-05-30)

README only: a G20 FDL cheat list (BDC_BODY `LHZ_CCM_IKF`, `SPURWECHSEL_ASSISTENT`, HU_MGU items).
Nothing on ambient colour. Confirms `BDC_BODY` / `HU_MGU` as the G20's coding targets. **Low** value.

### Public EdiabasX SGBD reference (emdzej.github.io/ediabasx-docs-sgbd), pages saved and parsed locally

The decisive source. `BDC_G05.prg` ("Body Domain Controller BDC-03 (from SP18)", rev 1.000, 113 jobs):
`SG_FUNKTIONEN` rows and tables for the interior light, quoted in PROTOCOL_FINDINGS.md. Also `BDC_G11.prg`
(DA5E = all slaves to full brightness for a time, **no colour**) and `bdc.prg` (DA62 the same). **High**
that the reference says so; **Medium** that this car's BDC is `BDC_G05` (`0F2680`) until `22 F1 50` is read.

### Forums (search summaries only: Bimmerpost refuses automated fetches, including the browser pane)

G20 threads *"Ambient light coding - 11 different colors [S18A-22-03-545]"*, *"Coding More Ambient Colors"*,
*"Bimmercode Expert Mode Cheat Sheet"*, the G80 *"definitive BIMMERCODE guide for custom AMBIENT LIGHTING"*,
the X3 LCI *"Ambient Lighting Colors & Combos"* thread, and the Garage Maslak cheat sheet: all describe
the same 360A/360D coding path, 10 custom colours possible, profile bytes in pairs mapping to the iDrive
menu entries (`360D` bytes 2/3 and 16/17 in one G20 example), "byte 97 must be 01" (G80 guide), and that
byte positions differ between models and software. One thread warns to code all menu items at once.
**Low** (unverifiable here). Links are in NEXT_STEPS.md for reading by hand.

## Searches run

GitHub/web searches for `G20 ambient lighting`, `BDC_BODY3`, `LIC_LCI_COLOR_LIBRARY_DATA`,
`LIC_LCI_COLOR_PROFILES_DATA`, `360A`, `360D`, `MGU ambient light`, `SOME/IP ... AmbientLight`,
`InternalTasu`, `Innenlicht`, `Ambiente`, `Farbwert`, `Lichtfarbe`, `ELC`, `UDS InputOutputControl`:
no public source names a SOME/IP lighting interface on the MGU; every hit on colour is the BDC coding
path; the only diagnostic-level RGB control found is the SGBD reference's `DA5E`/`E3D1`. BMW bulletins
(NHTSA copies) confirm the architecture: the BDC is the LIN master of the ambient LED modules, each with
its own address, configured by ISTA's "BDC LIN master" / NAD encoding.
